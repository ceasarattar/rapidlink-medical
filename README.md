# RapidLink Medical Referral Site

A deliberately minimal, static marketing site aimed at **Indiana personal injury attorneys**
who refer clients to RapidLink Medical Group PC.

Built with [TanStack Start](https://tanstack.com/start) (React 19 + Vite 7 + Tailwind 4).

## Running locally

Requires **Node.js ≥ 22.12**.

```bash
npm install
npm run dev
```

| Script | What it does |
| --- | --- |
| `npm run dev` | Dev server with HMR |
| `npm run build` | Production build into `dist/` |
| `npm run preview` | Serve the production build locally |
| `npm run lint` | ESLint |

## Privacy & HIPAA posture

This site is designed so that **it cannot receive protected health information in the
first place**. That is the whole compliance strategy, not a policy layered on top of a
system that collects data, but an architecture with nowhere for data to land.

Specifically, the site has:

- **No forms.** No contact form, no referral form, no input fields of any kind.
- **No database.** No Supabase, no ORM, no persistence layer.
- **No email pipeline.** No queue, no send log, no transactional email provider.
- **No analytics, tags, or tracking pixels.**
- **No third-party requests.** Fonts are system stacks, so no font CDN sees visitor IPs.
  The site loads exactly one image, from its own origin.
- **No cookies and no client-side storage.**

Attorneys are directed to phone and email. All clinical intake, records, and reporting
happen inside the practice's HIPAA-compliant eClinicalWorks system, never on this site.

> **Note:** email (including the ProtonMail address listed on the site) is not a HIPAA-secure
> channel for PHI. The site says so explicitly on the referral section and in the footer.
> Keep that language if you edit those pages.

- **No server.** Every route is prerendered to static HTML at build time, so there is
  no running backend to attack, misconfigure, or leak from.

### Security headers

Set in [`vercel.json`](vercel.json) and applied to every response:

`Content-Security-Policy`, `Strict-Transport-Security`, `X-Frame-Options: DENY`,
`X-Content-Type-Options: nosniff`, `Referrer-Policy`, `Permissions-Policy`.

The CSP allows `script-src 'unsafe-inline'` because TanStack Start emits one inline
hydration script (`$tsr-stream-barrier`). Since the site renders no user-supplied
content, there is no XSS vector to exploit.

Because headers are served by the host rather than by app middleware, they apply in
production only; `npm run preview` will not show them.

## Deploying

The build prerenders both routes and emits a fully static site to `dist/client`.
`vercel.json` pins the build command, output directory, and headers, so importing the
repo into Vercel needs no further setup. Requires Node 22.x or later on the build image.

There are **no environment variables**. If a future change introduces one, add it in the
Vercel dashboard and never commit a `.env` file.

### Before going live

This is currently configured as a **review deployment** and is blocked from search
engines in two places. Remove both when the site launches on its real domain:

1. the `robots` meta tag in [`src/routes/__root.tsx`](src/routes/__root.tsx)
2. the `Disallow: /` rule in [`public/robots.txt`](public/robots.txt)

## Structure

```
src/
  routes/
    __root.tsx      app shell, <head>, error + 404 boundaries
    index.tsx       home, attorney-facing pitch
    attorneys.tsx   referral process, capabilities, contact
  components/       SiteHeader, SiteFooter
  styles.css        Tailwind theme tokens
public/             favicon, robots.txt
vercel.json         build config + security headers
```

`src/routeTree.gen.ts` is generated by the router plugin, so don't edit it by hand.
