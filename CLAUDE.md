# CLAUDE.md

Guidance for Claude Code (and any agent) working in this repository.

/ **RapidLink Medical Referral Site** — a deliberately minimal, fully static marketing
site for Indiana personal-injury attorneys who refer clients to RapidLink Medical Group PC.
Built with TanStack Start (React 19 + Vite 7 + Tailwind 4), prerendered to static HTML.

---

## Toolchain

- **Node.js ≥ 22.12 is required.** Older versions will not build — stop and report rather
  than trying to work around it. The Vercel build image must also run Node 22.x+.
- Package manager is **npm** (there is a `package-lock.json`; no bun/pnpm/yarn lockfile).

## Commands

| Command | What it does |
| --- | --- |
| `npm install` | Install dependencies |
| `npm run dev` | Vite dev server with HMR (port **5173**; see `.claude/launch.json`) |
| `npm run build` | Production build → `dist/` (client + SSR, then prerenders every route) |

| `npm run lint` | ESLint over the repo |

## Auto-pull hook

This repo ships a **`UserPromptSubmit` hook** (in [`.claude/settings.json`](.claude/settings.json),
logic in [`.claude/hooks/git-autosync.sh`](.claude/hooks/git-autosync.sh)) that keeps the
local branch in sync with `origin` **before every prompt**. Behavior:

- **Up to date** → silent (no output on the happy path).
- **Behind + clean working tree** → fast-forward pull (`git merge --ff-only`), then reports
  the commit count and changed files.
- **Behind + dirty working tree** → pulls nothing and prints a warning that remote changes
  exist while your edits are uncommitted. Commit or stash, then pull manually.

Guarantees and notes:

- It only ever runs `git fetch` and `git merge --ff-only`. It **never** runs `git reset`,
  `git checkout --force`, `git stash drop`, `git clean`, or anything that could discard
  uncommitted work. A fast-forward cannot overwrite local changes or create a merge commit;
  if history has diverged, the hook stays silent and changes nothing.
- **"Dirty" means uncommitted changes to _tracked_ files only.** Untracked files (e.g. the
  `.claude/` dir was historically untracked) are ignored, so they do not wedge the hook into
  permanent warn-mode. A fast-forward can never silently clobber an untracked file.
- Because it is a **project hook**, each teammate's Claude Code will prompt them once to
  **trust** it before it runs. That is expected — approve it once.
- The hook only automates the **pull** side. Teammates receive your work only after **you
  push** your commits to `origin/main`.

## Project constraints (do not violate)

The compliance strategy is **architectural**: the site is built so it *cannot receive
protected health information (PHI) in the first place*. There is nowhere for data to land.
Keep it that way — these are hard constraints, not preferences:

- **No forms, no input fields of any kind.** No contact form, no referral form.
- **No database / persistence layer.** No Supabase, no ORM, no storage.
- **No email pipeline.** No queue, no send log, no transactional email provider.
- **No analytics, tags, or tracking pixels.**
- **No third-party requests.** System font stacks only (no font CDN). The site loads exactly
  one image, from its own origin.
- **No cookies and no client-side storage.**
- **No server.** Every route is prerendered to static HTML at build time — there is no
  backend to attack or leak from.
- **Email is not HIPAA-secure for PHI.** The site says so explicitly on the referral section
  and in the footer (including the ProtonMail address). **Keep that disclaimer language** if
  you edit those pages.
- **No environment variables.** If a future change needs one, add it in the Vercel dashboard;
  **never commit a `.env` file** (already gitignored).

### Security headers

Set in [`vercel.json`](vercel.json) and applied to every response: `Content-Security-Policy`,
`Strict-Transport-Security`, `X-Frame-Options: DENY`, `X-Content-Type-Options: nosniff`,
`Referrer-Policy`, `Permissions-Policy`. Headers are served by the host, so they apply in
**production only** — `npm run preview` will not show them. The CSP allows
`script-src 'unsafe-inline'` for TanStack Start's single inline hydration script; since the
site renders no user-supplied content, there is no XSS vector.

### Before going live

This is currently a **review deployment**, blocked from search engines in two places. Remove
**both** at launch:

1. the `robots` meta tag in [`src/routes/__root.tsx`](src/routes/__root.tsx)
2. the `Disallow: /` rule in [`public/robots.txt`](public/robots.txt)

### Don't hand-edit

`src/routeTree.gen.ts` is generated by the TanStack router plugin — never edit it manually.
