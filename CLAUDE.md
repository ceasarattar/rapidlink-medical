# CLAUDE.md

Guidance for Claude Code (and any agent) working in this repository.

**RapidLink Medical Referral Site:** a deliberately minimal, fully static marketing site
for a medical practice, aimed at Indiana personal injury **attorneys** who refer clients.

---

## Project constraints: hard requirements, NEVER violate

- **NEVER add booking, scheduling, or patient-portal features.**
- **NEVER make third-party network requests on page load.** No font CDNs, no external images,
  no remote scripts. Fonts are system stacks on purpose, so no outside service sees a visitor's
  IP. The one permitted outbound request is the Web3Forms POST on `/contact`, and it fires only
  when a visitor submits the referral form, never on load.
- **NEVER use em dashes or en dashes in any user-facing copy.** Use commas, colons,
  semicolons, or periods instead. (This file follows that rule too, deliberately.)
- **NEVER add AI-generated stock imagery.**
- **NEVER name an individual physician** anywhere in the site or in commit messages.
  Role descriptions such as "board-certified MD" are fine; individual names are not.
- **The audience is ATTORNEYS, not patients.** Keep all copy attorney-facing.
- **Never commit `.env` or any credential file.** `.gitignore` blocks `.env*`, `*.pem`,
  `*.key`; keep it that way. The single environment variable is
  `VITE_WEB3FORMS_ACCESS_KEY`, documented in `.env.example`. It is a public value by design
  (Vite inlines every `VITE_` name into the client bundle), so it is not a secret, but it
  still belongs in host config rather than in the repo.

### Why the constraints exist

The compliance posture is architectural: the site holds no patient data itself. There is no
database, no analytics or tracking pixels, no cookies or client-side storage, and no server.
Every route is prerendered to static HTML at build time. Preserve that property in any change
you make.

**The `/contact` referral form is the one exception, and it is a deliberate, owner-approved
narrowing of that posture.** It is attorney-facing: it collects a name, firm, email, phone,
and message, and relays them through Web3Forms to `info@rapidlinkmed.com`. Web3Forms is a
third party with no BAA in place, and the relay lands in ordinary email, so **the form is not
a PHI-safe channel**. The page says so above the submit button. Keep that notice, keep the
fields attorney-facing, and do not add any field that invites clinical detail about a client.
Anything clinical belongs in eClinicalWorks, never here.

Email, including the ProtonMail address listed on the site, is **not** a HIPAA-secure channel
for PHI. The site states this explicitly in the referral section and the footer. Keep that
disclaimer language if you edit those pages.

## Stack

TanStack Start (React 19, Vite 7, Tailwind 4), fully prerendered to static HTML.
No server runtime. Two routes: **`/`**, the attorney-facing landing page, and **`/contact`**,
the referral form.
Security headers live in [`vercel.json`](vercel.json). Its CSP allowlists
`https://api.web3forms.com` under both `connect-src` (the fetch path) and `form-action` (the
no-script fallback, where the form posts natively). Removing either silently breaks the form
in production while it keeps working in dev, since the header is served by the host.

`src/routeTree.gen.ts` is generated by the router plugin. Never edit it by hand.

## Toolchain

- **Node.js >= 22.12 is required.** Older versions will not build. Stop and report rather
  than working around it. The Vercel build image must also run Node 22.x or later.
- Package manager is **npm**. There is a `package-lock.json` and no bun, pnpm, or yarn lockfile.

| `npm install` | Install dependencies |
| `npm run dev` | Vite dev server with HMR, port **5173** (see `.claude/launch.json`) |
| `npm run build` | Production build into `dist/`, then prerenders every route |
| `npm run preview` | Serve the production build locally |
| `npm run lint` | ESLint over the repo |
| `npm run format` | Prettier `--write` over the repo |

`npm run build` must pass before any change is considered done.

Security headers are served by the host, so they apply in **production only**.
`npm run preview` will not show them.

## Auto-pull hook

This repo ships a **`UserPromptSubmit` hook** defined in
[`.claude/settings.json`](.claude/settings.json), with its logic in
[`.claude/hooks/git-autosync.sh`](.claude/hooks/git-autosync.sh). It keeps the local branch
in sync with `origin` before every prompt:

- **Up to date:** silent. No output on the happy path.
- **Behind, clean working tree:** fast-forward pull via `git merge --ff-only`, then reports
  the commit count and the changed files.
- **Behind, dirty working tree:** pulls nothing and warns that remote changes exist while
  your edits are uncommitted. Commit or stash, then pull manually.

Guarantees and caveats:

- It only ever runs `git fetch` and `git merge --ff-only`. It **never** runs `git reset`,
  `git checkout --force`, `git stash drop`, `git clean`, or anything that discards
  uncommitted work. A fast-forward cannot overwrite local changes or create a merge commit.
  If history has diverged, the hook stays silent and changes nothing.
- **"Dirty" means uncommitted changes to _tracked_ files only.** Untracked files are ignored
  on purpose, so a stray untracked file cannot wedge the hook into permanent warn mode.
- Every code path exits 0, so a network failure never blocks your prompt.
- Because this is a **project hook**, each teammate's Claude Code prompts them once to
  **trust** it before it will run. Approve it once per machine.
- **Important:** the hook loads only when Claude Code's project root **is this repository**.
  Open the session with `rapidlink-medical` as the working directory. If you open a parent
  directory instead, this file and the hook are not loaded.
- The hook automates only the **pull** side. Teammates receive your work after **you push**
  to `origin/main`.
